| 状态 | 完成时间 |

## 问题与最终结果

此前统一候选 CLI 没有接入最新公式关联交付，阶段评分分散在专用驱动中。用户要求确定方案、自审并补充
质量评分，随后明确授权“实施”。

现已提供 `rag-evidence-baseline-v1` 组合对象与 CLI：固定原索引、算法和预算，强制校验并交付结构关联，
由宿主分别计算候选、重排和实际交付覆盖及 MRR。一次正式 16 请求回放全部复现历史结果；未使用额外复测。

## 关键改动

- [组合与评分](../../../src/abaqus_sim_agent/evaluation/rag_evidence_baseline.py)：
  `RagEvidenceBaseline` 复用既有 backend、ranker、search 和关联交付；固定内容绑定，标签与搜索分离。
- [显式 CLI](../../../src/abaqus_sim_agent/evaluation/rag_evidence_baseline_cli.py)：
  普通请求与评测共用同一搜索方法；保存原结果、独立分数和 completion，失败不从分母中消失。
- [固定请求](../../../benchmarks/rag/rag_evidence_baseline_v1.json)：
  原 16 题及其标签保持，10 项旧必要证据与两个源段目标分别计分；不叫新 held-out。
- [测试](../../../tests/test_rag_evidence_baseline.py)：
  新增 25 项，覆盖正向关联接线、缺失/hash/归属错误、预算、标注隔离、OR/AND、失败计零、无标签、
  CLI 组合、漂移和中断。

本轮没有改被旧 manifest 绑定的检索/分块/投影/交付实现，没有重建索引或计算文档向量，
没有修改产品默认、API Catalog、Agent 或 Provider；没有新增依赖、生成模型/Abaqus 调用或 Git 提交。

## 验证结果

| 项目 | 结果 |
|---|---|
| 原请求、候选顺序、重排顺序、实际证据及关键元数据等价 | 16/16；分数绝对误差上限预先固定为 1e-5 |
| 合同 guard | 5/5 |
| 候选必要证据覆盖 | 9/10 = 90% |
| 重排 Top4 / 最终交付必要证据覆盖 | 均为 6/10 = 60% |
| 最终覆盖全部已标注条件 | 4/7 = 57.1% |
| 已标注必要父单元 MRR@64 | 0.635954 |
| 两个独立源段目标 | 1/2 完整交付 |
| 聚焦测试 / 全仓测试 | 66 passed / 970 passed、27 持证测试 skipped |
| 静态检查 | 两个新源码模块 Ruff / BasedPyright 通过 |
| 正式查询运行 | 一次，640 个本地重排 pair；未使用复测机会 |

原结果中的公式关联说明段实际交付数为 0，因此受控排序的组合测试单独证明接线；不将其计为真实检索收益。
运行失败即便留下部分证据也得零质量分；预先无标注的用例未评测，而不是满分。
对索引或实现漂移，整批结果不可验收。可捕获中断尽力落 incomplete；缺少有效 completion 不算完成。

## 已知限制与关闭依据

关闭依据是入口整合、合同验证、结果等价及分数可复核，不是把 6/10 设为质量合格线。
MRR 只看第一条已标注必要证据，不代表多证据覆盖；4/7 只覆盖全部已标注条件，不是完整问题正确率。

history 精度规则依旧完整送达；热膨胀说明仍在子片段重排第 63、未交付。Riks、API 语义相关性、复杂公式、
代表性新测试集、服务负载和 Agent 任务收益不由本计划解决。不自动开启下一轮优化，不切换默认产品路径。
