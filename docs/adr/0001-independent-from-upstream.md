# ADR-0001：与上游 AbaqusAgent 保持独立实现

## 状态

已替代

由 [ADR-0005](0005-traceable-upstream-reuse.md) 替代。

## 日期

2026-08-19

## 当时遇到了什么

上游 AbaqusAgent 已经实现多角色工作流、案例检索、输入文件生成、执行和错误修复，可作为重要机制参考。但本项目需要展示作者对架构、可靠性和评测的独立理解，直接 fork 或沿着上游代码改造会削弱设计解释力，也容易把上游的状态和执行边界问题一并继承。

## 最后决定

上游仓库单独克隆到工作区的 `references/AbaqusAgent`，本项目使用独立 Git 仓库、包结构、领域模型、测试和文档。可以研究上游的流程和实验方法，但不直接复制源码。若以后确有必要引入上游代码，必须单独标明来源、修改内容和 MIT 许可证义务。

## 为什么这样选

独立实现让每个架构决定都能从问题和约束推导出来，同时保留上游仓库用于机制核对和结果比较。两套 Git 历史分离，也便于持续拉取上游更新而不污染作品仓库。

## 没有采用的方案

- Fork 后重构：启动更快，但提交历史和大量初始设计不是我们的工程证据。
- 把上游源码复制进项目：失去可追溯来源，容易造成许可证和原创性表述问题。

## 带来的影响

- 有利：架构、测试和提交历史能够真实反映我们的设计与实践。
- 代价：需要自行实现基础协议和工作流。
- 风险：可能重复上游已经完成的低价值工作，因此每个阶段都应先研究机制再独立实现。

## 落实与确认

- 实施情况：已落实独立目录和 Git 仓库；功能实现刚开始。
- 参考基线：上游提交 `f5462b3eaf34d21a958f495b80e40df45b3f39db`。
