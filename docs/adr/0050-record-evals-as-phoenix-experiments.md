# ADR-0050：保留 Evals 执行，将结果自动记录为 Phoenix 实验

## 状态

2026-10-07：[ADR-0051](0051-manage-phoenix-lifecycle-for-evaluation.md) 进一步确定测评直接启停服务及原生默认数据库，替代服务需事先独立运行的使用前提；Evals、证据与派生实验的职责不变。

已采纳，2026-10-06。用户确认不迁移评测引擎，在评测期间运行 Phoenix，自动登记题集、实验与逐题结果，不建设离线队列和自动补传。

部分替代 [ADR-0044](0044-local-phoenix-observability.md) 中评测仅上传 span annotation、不建立 Dataset/Experiment，以及评测开始时不要求服务可用的范围。CLI/Web 普通产品追踪及业务状态所有权不变。

## 背景与选择

仅把已有评分挂在 Trace 上，不能直接使用 Phoenix 原生的题集和实验比较页面。迁移执行引擎会涉及现有 Case 生命周期、异常、统计与恢复接线，但平台提供了只创建记录、写入已完成运行及评分的接口，因此无需重新执行 Agent 或评分器。

选择继续由 Pydantic Evals 组织任务与评分，通过同一个显式 `--phoenix` 开关同步原生实验记录。另一种方向是由 Phoenix Experiments 接管执行与题集；它减少两种结果对象的转换，但让现有评测行为随平台执行器变化，不是本次需要解决的问题。

## 决定

- 支持范围为公开力学 `run/continue/resume`，以及任务基线共享运行入口，包括离线 demo、真实 pilot 和 simple modeling。没有 `--phoenix` 时不创建客户端、题集或实验回执。
- 启用后，在任何模型或 Abaqus 任务启动前通过官方 client 查找或创建题集，并创建本次实验。服务不可达、题集内容不一致或登记失败时停止本次调用，不消耗执行预算。
- 题集以公开输入和元数据的内容摘要命名；相同题集复用同一个平台版本，输入变化使用另一份题集。复用前核对实际内容，拒绝网页修改后的同名题集；不上传隐藏参考答案。
- 每次实际运行、continue 或 resume 调用建立独立实验，不覆盖前次运行。只读 report 不新增实验；当前调用未选择执行的 Case 不作为新的运行写入平台。
- 原生生命周期先完成已有的业务保存与收尾，再复制实际输出、断言、数值、标签、评分异常和可验证的 Trace 关联。不得调用 Phoenix `run_experiment`、重跑任务或重算判分。
- 实验记录的耗时是 Case 执行与评分经过时间，不能替代累计 Agent active wall。首次与最终提交分别保存对应评分；平台默认均值不替代本地报告的计划分母和完整性判定。
- 运行中写入失败立即记录错误，停止本次后续实验写入；Evals 按原合同收尾并保留本地结果。正常收尾后抛出明确的记录不完整错误；业务异常和取消优先传播，不能被观测失败覆盖。
- `telemetry/experiments/<invocation_id>.json` 只保存平台身份、版本、已记录 Case 和写入错误，是观测回执，不是执行 ledger、补传队列或可恢复状态。不会通过它自动重跑或补发历史结果。
- 原始业务证据、判分与汇总始终由本地 Service/verifier/Evals 报告拥有。Phoenix 是派生视图；实验记录缺失不改写 outcome，也不把缺失或未评分解释为通过。

## 代价与边界

每题结果发布增加本机 HTTP 请求及序列化开销，平台不可用会使显式开启的评测在启动阶段报错。中途故障仍可能产生部分平台记录；无需为了本机单用户使用新增持久队列。Trace 导出仍沿用官方 SDK 的原合同，实验记录成功不证明每个 span 都已送达。

已有冻结 worker、批次、seal 和成绩保持原值。新代码只进入新准备的运行；不把历史评分批量导入平台或重新生成历史追踪。任务基线的后置独立验收和人工审查仍留在原本地报告，不被任务阶段的实验输出冒充。

当前实现与使用入口见 [系统框架](../architecture/system-framework.md#可选启用的遥测)和[力学报告](../../benchmarks/coding/result_reporting.md#phoenix追踪与评分)。
