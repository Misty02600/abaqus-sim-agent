# ADR-0049：普通产品只从可选目录选择模型

## 状态

后续默认行为调整（2026-09-29）：用户进一步确认取消首项/默认模型自动选择。新会话必须明确选择提供商和型号，
网页初始为待选择状态，未选模型不能发送；登录只增加提供商连接，Codex 可显示为已连接但模型列表为空。
Web 服务不再提供默认模型启动参数。此处保留原决定的演进记录，当前字段规则以[配置合同](../architecture/configuration-reference.md#模型发现与连接)为准。

已采纳，2026-09-29。用户明确要求不再让普通用户填写目录外的模型 ID。
替代 [ADR-0046](0046-use-native-providers-and-available-model-selection.md) 后续澄清与
[ADR-0048](0048-fetch-models-dev-with-local-cache.md) 中允许完整明确型号绕过候选列表的部分。

## 背景与决定

按名称取得 SDK profile 是匹配内置规则与元数据，不是远端验证；同名模型的普通 API 与订阅渠道可能有不同限制。
第三方目录已承担候选资料维护，没有必要再让普通用户用手填名称弥补缺项。

- 网页只提供可选模型下拉框，移除目录外型号输入。选项失效时明确提示重新选择，不自动换模型。
- CLI 的 `--model` 与 API 的 provider/name 仅用于指定当前可选列表中的条目；新建会话和显式换模型共用此限制。
  不在列表的明确选择直接报错，不再调用按名称推导作为放行路径。未指定时仍取匹配候选的稳定首项。
- 目录获取失败且没有有效缓存时，新建会话失败，不因 SDK 能匹配名称而绕过。
  无候选的提供商暂不支持新建；当前 Codex 没有目录，保留凭据管理以服务已有会话，不以手填方式开放新建。
- 旧会话恢复沿用保存的模型与窗口，不重新要求其出现在今日目录；重复指定同一型号仍保持原窗口。
  主动换型号则选择当前候选，继续保留累计 usage、权限与执行证据。

目录来源仍按0048直接获取 models.dev并缓存，现有 OpenCode 局部适配名单保持原范围。
SDK继续处理原生协议与能力；候选匹配不是账号授权或真实服务兼容保证。代价是未收录型号即使可调用，
普通产品也暂不开放；程序化评测/底层模型装配不因此变成新的用户绕过入口。

当前字段和错误语义见[模型发现与连接](../architecture/configuration-reference.md#模型发现与连接)。
