# ADR-0051：测评直接启停 Phoenix，使用原生默认数据库

## 状态

已采纳，2026-10-07。用户确认：测评显式启用 Phoenix 时直接启动服务，不复用已有实例；结束后关闭本次服务、保留数据库；使用原生默认 6006 端口和 `~/.phoenix/phoenix.db`，不另设项目数据目录，不新增历史查看命令或补传队列。

部分替代 [ADR-0044](0044-local-phoenix-observability.md) 中服务始终由用户独立启动的范围，并具体化 [ADR-0050](0050-record-evals-as-phoenix-experiments.md) 的测评启动前条件。普通 CLI/Web 可选追踪仍连接用户自己启动的服务。

## 背景与取舍

原接线要求先启动 Phoenix，再为评测配置 collector 地址。用户希望一个测评命令完成这些步骤，同时沿用 Phoenix 自身支持的本机持久数据库。复用或接管已有实例会扩大进程所有权判断，按批次创建临时数据库又不利于保存历史，因此选择每次启动新的服务进程、继续读取同一默认数据库。

完整 Phoenix 服务保留在独立 uv 工具环境，避免加入普通 Agent 的运行依赖。直接把服务包安装到产品环境并同进程运行也是可行方向，但会合并两边的依赖和事件循环生命周期。隔离环境的代价是需要 uv，首次启用可能下载服务端依赖；服务端版本固定为已验证的 20.16.0。

## 决定

- `--phoenix` 默认关闭。当前接线的评测 CLI 在显式启用时启动本次服务；普通产品 CLI/Web 不自动启动。
- 自动模式固定使用 `http://127.0.0.1:6006`。端口占用即报错，不复用、不接管、不终止已有服务，也不自动换端口。
- 使用 `uvx --python 3.12 --from arize-phoenix==20.16.0` 运行独立宿主，调用官方 `launch_app(use_temp_dir=False)`。不设置工作目录或数据库连接串；不继承调用方的 Phoenix 服务端覆盖变量，数据库由 Phoenix 默认逻辑定位到 `~/.phoenix/phoenix.db`。
- 自动服务只用于本机 HTTP。固定版本默认另外启动的 gRPC 接收器在该隔离宿主内关闭；不修改安装文件，不让该适配影响普通产品或用户独立启动的 Phoenix。
- 父进程等待自己启动的宿主发出就绪信号后，才初始化追踪并进入原评测流程。不通过探测另一个服务的 HTTP 成功响应宣布本次启动完成。
- 初始化、模型执行、评分和本地报告职责继续遵循 ADR-0050。服务启动时间不进入 Agent 活动时间预算。
- 结束、异常或取消时，先由现有调用链保存本地结果并关闭追踪导出器，再关闭宿主 stdin，由宿主调用官方 `close_app()`。关闭超时才终止本次受控进程树；不按进程名或端口查杀其他服务。
- 不删除默认数据库。正常关闭、重启读取以及协作式取消应验证；不承诺断电或强杀父子进程时一定执行 Python 清理逻辑。
- `PHOENIX_COLLECTOR_ENDPOINT` 在自动模式下临时统一为默认地址，退出后恢复调用方环境；普通 CLI/Web 仍按原合同允许设置本机 collector 地址。
- 不迁移先前 16007 验证服务的数据，不覆盖冻结 worker、批次和报告，不新增后台守护管理器、历史查看命令或补传系统。

## 后果与边界

同一默认端口同时只能由一个服务使用；需要已有 Phoenix 保持运行时，用户应先结束它再启动自动测评。数据库可以保存其他项目的数据，程序不清空已有记录，以既有项目名、题集内容身份和独立实验 ID 区分。

评测结束后网页服务也关闭；以后可用 Phoenix 自带的 `phoenix serve` 命令读取相同数据库。依赖安装、启动失败或数据库不可用时不执行测评；观测与评测失败仍分别表达，原业务异常和取消优先传播。

当前入口、环境与支持边界见[配置合同](../architecture/configuration-reference.md)和[系统框架](../architecture/system-framework.md#可选启用的遥测)。

实现已经完成。验证范围与数据见[2026-10-07生命周期验证](../../benchmarks/observability/phoenix_lifecycle_20261007.json)，不代表重新执行了真实模型或力学测评。
