# ADR-0038：统一执行前语法检查与非阻断静态反馈

## 状态

已采纳（2026-09-22）。用户确认：移除静态检查双模式，语法错误执行前阻断，其余诊断与实际执行结果一起返回；由 Codex 实施。

## 背景

旧预检有 `advisory` 和 `enforced_verified` 两套控制流。前者首次暂停、原样重试可放行，后者依据有限
API 负例阻断。它们都过滤诊断；未定义名称也被忽略。静态声明与 Abaqus 动态对象存在差异，有限探针
不能证明普遍适用性。用户接受模型在真实报错后自修复，也接受正常失败，希望减少特殊规则和额外往返。

## 决定

- 普通 CLI 的可选 BasedPyright 预检只有 `off` / `on`，默认 `off`；启用时绑定固定 abqpy 来源和引擎版本。
- 两个 Python runtime 工具始终在权限、路径策略之后、预算预留和外部进程之前检查当前脚本的 Python
  3.10 语法。使用宿主解析器，不执行脚本；编辑过程允许不完整文件。语法错误或无法检查脚本时拒绝本次执行。
- BasedPyright 的 error/warning 均作为静态提示，不按案例规则删改或提升为阻断。反馈最多保留 20 项，
  error 优先；单条消息最多 4000 字符。省略数量、消息截断和完整原始输出分别留证。
- 静态诊断、超时或不可用状态与真实执行结果一起返回，不产生额外确认或原样重试放行阶段。真实运行
  失败优先解释；成功后不要求仅为清空静态告警而改代码。检查器故障不冒充 clean 或脚本失败。
- 结果缓存按 runtime 种类、相对路径和实际 bytes 的 SHA-256 绑定；只有完成的分析可复用。检查期间文件
  变化仍拒绝执行未检查的新版本。累计 usage、执行证据与恢复基线继续归宿主所有。
- 预检可与普通 `ask_user`、文字答复、Shell 和后台 Solver 会话组合。它不改变 Solver 权限、CAE 内直接
  submit/wait 拒绝、工作区边界或最终 verifier。
- launch 升到 v8；resume 三种当前协议分别使用 v6/v7/v8。旧模式和旧 state 显式拒绝，不自动迁移。
  历史实验的原始配置、源码快照、证据和成绩不改写；新评测使用当前 off/on 合同。

## 取舍

没有保留原样重试逃生口：它增加一次模型往返，却不要求修复。没有继续依赖 API 案例表强制阻断：维护
和误阻断成本不符合当前需求。没有把所有静态 error 当成硬错误：动态类型诊断不等于运行失败。

代价是部分可静态怀疑的错误仍会消耗一次运行；分析本身也有开销，因此继续显式启用。语法解析通过不
保证全部编译语义、API 行为或物理正确，也不构成沙箱。本决定不声称提高了真实模型成功率。

## 替代关系与验证

替代 [ADR-0018](0018-enforce-verified-abaqus-aci.md) 的双模式、编辑语法门和 API blocker 策略；保留其
权限优先、原始证据、来源绑定原则。沿用 [ADR-0030](0030-drop-pre-release-coding-run-state-compatibility.md)
的开发期 state 拒绝策略。ADR-0016/0018 的历史文本和冻结实验继续保留。

离线测试覆盖运行前语法拒绝、告警伴随执行、检查器故障、文件变化、诊断完整性/截断、缓存恢复、
旧模式拒绝及普通会话工具组合。真实 Provider/Abaqus 收益需要独立的新实验，本次不执行。
