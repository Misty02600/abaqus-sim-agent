## 背景

此前以模型偏好、Abaqus 安装路径、Catalog 路径为理由引入了用户/项目配置文件。逐项讨论后发现：模型可以
通过本次选择及程序默认策略决定；Abaqus 使用固定的 `abq2024` 命令；Catalog 应由程序管理并定位。
当前没有足够明确的长期个人偏好或逐项目默认值需求，支撑额外的文件发现、优先级、损坏处理和维护负担。

项目文件还会参与 workspace snapshot；自动读取项目设置既增加启动输入，又没有消除恢复时的工程一致性要求。
继续仅为模仿 Pi 的文件层次维护这些机制，与当前简化产品的目标不符。

## 决定

- 配置来源收敛为**程序默认值、CLI/Web 本次显式输入、必要的会话记录**。不自动读取、创建或回写用户级
  `%LOCALAPPDATA%/abaqus-sim-agent/settings.json` 或项目级 `.abaqus-sim-agent/settings.json`。
- 新 CLI 会话采用显式参数 > 程序默认；Web 采用本次创建输入 > 本次服务启动选项 > 程序默认。
  Web 的启动选项只存在于当前进程，不成为持久化用户偏好。两端保留同一套公共类型、校验和装配规则。
- 恢复使用保存的 request/launch 与已提交修订，不重新套用新默认。仅保存影响会话继续执行的实际条件、
  必要的资源身份和证据；端口、显示、是否打开浏览器、本次观测设置与凭据仍由当前宿主管理。
- 普通产品直接以 `abq2024` 启动 vendor CLI，找不到命令时明确报错。移除普通产品的安装路径选择输入，
  不把操作系统定位可执行文件重新包装成用户安装路径配置。保留受控进程、权限、超时和实际命令证据。
- Catalog 作为程序管理的固定资源，移除普通用户的目录选择输入；内容版本/hash 仍绑定会话。
  包内资源、应用数据目录、分发与初始化细节由独立调研确认，本决定不宣称已打包、已安装或许可已核实。
- 模型接入优先复用 Pydantic AI 内置 provider、模型目录和能力/窗口元数据；OpenCode 自定义接入可暂时只
  支持 DeepSeek，但该限制不能限制所有内置 provider。默认选择顺序、未知元数据及 DeepSeek 专用策略的
  泛化由独立模型方案确认；不在这里擅自定成“任意模型列表的第一项”，也不新增保存默认模型的用户文件。
- 当前已有偏好文件不迁移、不删除；撤回代码后不再当作配置读取。原文件如仍位于 workspace，仍是普通
  工程文件，不豁免快照校验。冻结评测数据、合同和旧报告不回填。

## 保留与撤回的边界

保留 shared CLI 参数适配、typed 输入与最终组合校验、按会话绑定加载资源、运行权限/usage 分离，以及
只对允许字段应用的 amendment。移除文件偏好来源，不等于删除所有 CLI 选项、工具权限或会话记录。

本方案只取消已经识别为多余的持久化来源和普通用户路径配置，不顺带开放实验 profile，也不引入新的配置框架。
只有后续出现明确的用户偏好需求，才重新评估持久化设置；不能将本次保留的宿主启动选项隐式保存为偏好文件。

## 代价与未完成事项

用户跨会话重复选择某些非默认参数的便利性降低；这是当前接受的简化取舍。模型支持扩展与 Catalog 分发尚待
各自方案确认。当前源码仍读取两级偏好，并要求 Catalog 路径、保存 launcher 路径，文档不得声称撤回已经完成。

实施范围、逐字段去向和验收标准见[配置逐字段合同的修订方案](../architecture/configuration-reference.md#已确认的修订方案)。
