# ADR-0047：保存宿主凭据并随应用分发模型目录

## 状态

2026-09-29：模型目录的生成打包、Pi 提取与 SDK 名称表兜底由
[ADR-0048](0048-fetch-models-dev-with-local-cache.md) 替代；凭据存储决定继续有效。下文保留当时取舍。

已采纳，2026-09-29。用户要求参照 Pi 完成凭据保存和登录后的模型选择，能够用轻量方案解决的直接实施。
部分替代 [ADR-0046](0046-use-native-providers-and-available-model-selection.md) 中凭据仅在进程内保存的决定，
并明确第三方候选目录来源；其原生 provider、共享选择和恢复不自动换模型的约束继续有效。

后续落实澄清（2026-09-29）：用户确认 Copilot 正常使用 Pydantic AI 原生接口，不额外设计令牌交换或续期。
已移除下文当时记录的“带 expiry/refresh 就拒绝保存”实现限制；保存并使用 SDK 返回的 access token，
失效后重新登录。宿主凭据所有权和原生 provider 方向不变，当前细节以[配置合同](../architecture/configuration-reference.md#模型发现与连接)为准。

## 背景

SDK 的 `known_model_names()` 并非完整模型目录。Codex、Copilot 等 provider 能认证和调用，原菜单却无条目；
只允许手填 ID 不能解决发现问题。进程内保存登录结果又导致重启重复登录。这两项是宿主产品职责，不能由
“模型调用交给 Pydantic AI”推导为已完成，也不应把凭据保存误当成重新引入用户偏好。

## 决定

- CLI/Web 共用用户应用数据目录中的 `auth.json`。交互输入或登录成功后保存，保存失败不能显示成功；
  本应用保存值优先于启动时捕获的环境密钥，再沿用 SDK 已有本机认证。环境密钥不自动落盘。
- 使用明文 JSON、文件权限、跨进程写锁和原子替换；不引入系统密钥库、DPAPI、数据库或用户可选存储路径。
  Windows 使用用户应用数据目录的文件系统权限，不声称 POSIX mode 等同于额外 Windows ACL 加固或加密。
- Codex 通过 SDK `credential_source.load/save` 保存刷新结果。更新保留其他 provider 的记录；刷新写入前比较
  读取版本，避免覆盖新登录或复活已删除凭据。SDK 的跨进程刷新检查仍是 best-effort，不承诺 OAuth exactly-once。
- 删除只移除本应用凭据，不修改环境或其他应用的登录、不撤销服务端账号授权、不改变会话模型。
- 候选目录由维护脚本从 models.dev 生成，Codex 缺项从固定 Pi 提交的生成器数据提取；记录 URL、SHA-256、
  Pi commit 和许可证，随应用打包。运行时不下载、不新增刷新间隔或目录路径配置；更新目录随应用发布。
- 第三方目录只提供型号、窗口、工具/文本能力和停用标记。使用通用元数据筛选，无本项目型号黑名单；
  已覆盖 provider 不混回 SDK 的过时名称。尚无目录的 provider 可沿用 SDK 候选，完整明确的型号仍可交 SDK 校验。
- SDK profile 继续负责协议能力。新会话窗口使用目录与 SDK 已知值中的较小值，只有一方有数据则使用它；
  既有必要的 OpenCode/DeepSeek 适配仍局部保留。保存后恢复不重算窗口。

## 取舍与边界

与每次登录在线拉模型相比，包内目录不增加认证后的联网故障点，但可能滞后于服务商；目录表示已知候选，
不是账号实际授权清单。列表首项保持稳定排序，不保证最新或最好；没有手工维护推荐表。

Azure 的部署名、本地模型服务的安装清单不能由公共目录推导。本次不新增部署发现控制面或用户窗口配置，
也不把公共模型名称冒充这些实例的可用部署。明确型号缺少窗口资料时继续拒绝创建。

GitHub Copilot 的原生设备流程需要调用方自己的 OAuth Client ID；本应用不借用其他客户端身份。
当前 SDK 不提供该流程的短期令牌续期，带 expiry/refresh 的授权明确拒绝保存为长期登录；已有长期 Token 可保存。
这与 Codex 已有的原生刷新回调分开，不宣称所有 OAuth 形态均已支持。

本地明文存储与 Pi 的基本方案一致，文件不能提交或分发。增加系统加密、在线模型发现或 OAuth 客户端注册，
均需具体需求，不作为本次基本体验的前置条件。
