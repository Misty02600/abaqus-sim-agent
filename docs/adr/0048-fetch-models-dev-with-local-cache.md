# ADR-0048：直接获取 models.dev 并缓存有效目录

## 状态

2026-09-29：目录外明确型号输入由 [ADR-0049](0049-select-product-models-only-from-available-catalog.md) 替代，
普通产品改为只从可选列表选择；本记录的目录获取与缓存决定继续有效。

已采纳，2026-09-29。用户确认直接读取 models.dev、程序自动缓存，要求评估 SDK 名称表兜底的必要性，
并允许 Codex 没有合适来源时暂不维护额外目录。
替代 [ADR-0047](0047-persist-host-credentials-and-bundle-model-catalog.md) 的模型目录生成/打包及 Pi 数据提取部分；
其凭据存储决定继续有效。[ADR-0046](0046-use-native-providers-and-available-model-selection.md) 的原生调用、
显式选择/稳定首项及恢复不重选仍有效。

## 背景

原目录需要维护者抓取 models.dev、解析固定 Pi 提交的 TypeScript 数据，再生成文件随应用发布。
这把型号更新绑定到产品发布，也增加了对另一项目内部源码的依赖。用户需要可更新的候选资料，
没有要求首次离线安装即拥有完整模型目录。

SDK 名称表兜底经本项目 Pydantic AI 2.51.0 与当时目录核对，仅 Bedrock Mantle 的11项中有3项通过当前校验；
Heroku 的23项因窗口资料不足均未通过，TypeSafe 的2项未通过当前能力要求，其他未覆盖 provider 为0项。
为这3项保留另一套目录来源，不足以抵消理解和排错成本。明确型号仍可由 SDK 校验，无需把名称表当准入名单。

## 决定

- 模型候选主来源固定为 `https://models.dev/api.json`，使用无提供商凭据的公开请求。只消费型号、窗口、
  文本/工具能力及停用标记，不把远端地址或认证声明直接变成本项目的调用配置。
- 每个进程首次需要目录时获取并验证数据；之后使用内存快照。网页的“刷新可选模型”明确重新获取；
  CLI 新进程自然重新尝试。不设置用户可调的目录路径、刷新周期或额外偏好文件。
- 成功数据原子写入用户缓存目录的 `models/models.dev.json`。网络或数据校验失败时使用最近有效缓存，
  首次无有效缓存则明确报错。失败响应不覆盖缓存；缓存写入失败可使用本次内存数据并记录警告。
- 移除维护者生成脚本和包内模型数据，不再解析 Pi 源码，也不再用 `known_model_names()` 补候选。
  提供商ID的必要映射与协议范围筛选保留；OpenCode 原有局部 DeepSeek 适配名单不扩大。
- 当前 models.dev 没有 Codex 订阅目录，因此不维护额外 Codex 候选表。原生登录和明确型号输入仍保留；
  SDK 窗口/能力未知时继续拒绝新建，不猜填。上游新增有效目录后可直接消费，不复制普通 OpenAI API 清单。
- 连接发现独立于目录下载。没有凭据时不必下载目录；下载失败不妨碍配置凭据。
  自动选择需要有效目录，完整明确的型号可使用 SDK 元数据；现有会话恢复沿用保存的型号和窗口，不依赖新目录。

## 取舍

获得独立于应用发布的目录更新，同时新增首次列表获取的网络依赖；有效缓存承担离线使用。
目录是第三方公共资料，不是账号授权清单，也不证明真实模型请求兼容。框架负责原生协议和能力，
宿主继续按保存窗口管理上下文，不因目录变化重算旧会话或自动更换模型。

本决定只涉及模型目录。领域 Abaqus API Catalog 的包内分发与证据身份合同不变。
实现和逐字段合同见[模型发现与连接](../architecture/configuration-reference.md#模型发现与连接)。
