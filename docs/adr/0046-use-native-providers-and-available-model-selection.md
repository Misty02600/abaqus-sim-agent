## 背景

最初的模型接入围绕 DeepSeek 与 OpenCode，提供商支持、固定默认型号、上下文窗口和会话恢复彼此耦合。
扩大接入范围后，框架完整目录、已经配置认证的模型、实际可执行的远端模型又容易被混为同一概念。
仅把全部 provider 放进下拉框，或把没有明确选择的请求继续交给 DeepSeek，都不能表达当前用户的连接状态。

这些规则共同影响 CLI/Web 的公开行为、模型适配层的职责、凭据所有权与会话恢复，具有独立于偏好文件格式的
长期约束。[ADR-0045](0045-use-explicit-run-options-without-preference-files.md) 已确定不读取用户/项目偏好文件；
本决定在该来源边界内明确模型如何接入和选用。

## 决定

### 模型协议交给框架，专用接入保持局部

普通产品优先复用 Pydantic AI 原生 provider、模型工厂、能力 profile 与工具循环；Harness 负责 Coder 能力组合。
框架已有的请求序列化、流式工具参数拼接和输出校验不在应用层重新实现。
OpenCode 的 DeepSeek 专用协议保留独立适配，其型号限制与额外参数不能施加到所有原生 provider。
具体 SDK 安装范围和已接线的提供商由当前架构文档说明，不把安装或离线接线等同于真实远端验收。

### 连接发现与模型选择使用不同列表

添加连接的入口展示项目可接入的提供商，不因尚无凭据而隐藏它们。
普通模型选择器只展示认证来源已配置、SDK 可用且满足框架工具/文本能力与窗口元数据要求的条目。
CLI/Web 共用筛选和排序逻辑；列表不包含密钥或令牌。

“可选”表示本地接线条件具备，不表示已经逐个请求远端验证了密钥、账号权限、额度或协议兼容。
窗口或内置型号资料缺失时不伪造条目，也不要求用户猜填窗口。
列举模型不执行登录、不刷新令牌或逐个发送模型请求；用户主动连接及实际模型请求各自承担对应认证流程。

### 新会话按本次选择或可用首项确定模型

先按 ADR-0045 合并本次显式输入：CLI 参数，或 Web 创建输入优先于当前服务启动输入。
已指定 provider/name 时只在可用列表中匹配该选择；只指定其中一项时取匹配子列表首项。
两者都未指定时取完整可用列表首项。没有匹配项时明确报错，不改用其他模型；列表为空时提示配置凭据或登录。

列表按 provider ID、model ID 的字符串升序排列，界面展示和自动选择使用同一顺序。
不固定 DeepSeek 默认型号，也不维护各提供商的推荐默认型号表。稳定首项不是质量、价格或新旧排序。
本次选择只进入当前会话，不自动记为下一次默认，也不引入用户/项目默认模型文件。

### 凭据属于宿主，模型合同属于会话

API Key、当前 Web 登录结果与已有 SDK 本机认证来源由宿主取得；不写入 request/launch、工程文件或模型消息。
交互输入的密钥和 Web 登录结果保留在当前服务进程；已有 SDK 凭据存储沿用其原合同。
同一服务可为不同会话按各自保存的 provider 提供凭据，不能用服务当前默认 provider 约束旧会话。

会话保存实际采用的 provider、模型、窗口及必要的非凭据连接绑定。恢复使用这些记录与合法修订，
不重新从今日可选列表挑选，不因添加连接、目录顺序变化或凭据缺失而自动换模型。
明确换模型继续使用既有 amendment，重新校验相关策略与窗口，保留累计 usage 和执行证据。

### 内部元数据与兼容性不转嫁成普通用户配置

普通 CLI/Web 不提供通用自定义 API 地址或上下文窗口输入。窗口由框架及已有的必要 provider 适配确定，
创建时记录，恢复时沿用；未知窗口模型暂不进入新会话可选列表。
端点遵循 provider SDK 的原生接线；不因此宣称任意代理、自部署或云部署场景均已支持。
开发期不兼容会话按 [ADR-0030](0030-drop-pre-release-coding-run-state-compatibility.md) 明确拒绝，不自动迁移或改指向。

不在应用层另建型号黑名单、通用模型能力库或复制 Pi 的兼容例外全集。
先核查框架已有 adapter 的处理；有实际故障证据时再评估具体适配修复或上游修正。
上游元数据可能有缺漏，SDK 实现流式接口也不证明每个远端型号都支持。实际不兼容时保留明确错误，
不把通用非流式重试或自动换模型作为隐含兜底。

## 取舍

- 相比固定单一提供商或型号，新会话默认随已配置认证的可用集合而变化；必须显示并保存最终选择，恢复保持原值。
- 相比维护每家提供商的推荐型号表，稳定首项减少目录维护，但不保证自动选到最新或最适合编码的模型。
- 相比手填任意端点与窗口，本次范围减少用户输入及恢复组合；缺少框架型号/窗口资料的接入暂不能创建普通会话。
- 相比自建兼容库，复用上游降低长期维护成本，也接受元数据不完整和真实请求可能失败的边界；这不能扩大能力声明。

## 关系与落实

本决定具体化 ADR-0045 中原先交给独立模型讨论的部分；配置来源和内部资源管理仍由 ADR-0045 约束。
沿用 [ADR-0043](0043-separate-model-preferences-from-session-contracts.md) 的会话/宿主凭据分离与恢复不自动换模型原则；
其用户/项目偏好文件方向仍由 ADR-0045 部分替代，不在此恢复。

当前工作区已接入上述选择流程。稳定公开语义、逐字段持久化与实现入口分别见
[模型配置与兼容](../architecture/technology-stack.md#模型配置与兼容)和
[配置逐字段合同](../architecture/configuration-reference.md#模型发现与连接)。
验证覆盖共同列表、默认选择、显式选择失败不回退、恢复绑定、凭据不落盘和必要的 SDK 模拟协议场景；
离线与假模型浏览器验证不代表所有 provider、真实登录或持证仿真已经验收。

models.dev、LiteLLM 等第三方目录目前仅做过调研，是否作为项目模型目录来源尚未决定。
本决定没有引入另一套模型调用框架、目录下载/缓存策略或新的用户配置。
