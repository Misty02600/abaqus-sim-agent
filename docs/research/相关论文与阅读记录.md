# 相关论文与阅读记录

核验日期：2026-09-13。返回[调研索引](README.md)。

这里保存与本项目有关的论文、参考实现及阅读结论。重点是：模型缺少哪些领域知识，系统怎样补足，
实验实际验证了什么，以及哪些经验能够迁移到 Abaqus Coding Agent。文献中的设计不自动成为本项目的
架构决定；当前实现与采用情况以[架构总览](../architecture/overview.md)和[ADR](../adr/README.md)为准。

工程项目的横向调研另见[科研与工业 Agent 项目参考价值](科研与工业Agent项目参考价值.md)：
记录 pymechanical-mcp、CadAgent、sim-plugin-abaqus、OpenHands SDK 和 mini-swe-agent 的具体机制、
固定源码依据、与本项目的重叠及验证边界。项目调研与下方论文详读状态分别记录。

当前纳入十项工作。**AbaqusAgent 保留既有论文与固定源码详读；ChatCFD、2D Frame、ALL-FEM、
Generic Harness、MCP-SIM 和新增 FEM-Bench 已补充原文关键部分核查，其中 ChatCFD、MCP-SIM 另检查了
固定提交的关键源码；其余三项仍为书目与阅读定位。** 本轮未复现第三方实验。具体证据与建议统一收录于
[专业能力与工业评测原文核查](专业能力与工业评测原文核查-2026-09-13.md)，不在书目中重复展开。
下表的“未核实”表示本次证据边界，不表示对应论文或代码一定不存在。

**本地 PDF 已归档（2026-09-13）：10 项工作、11 份文件。**
[归档索引](../../../references/papers/README.md)提供逐篇文件链接与版本说明，
[归档清单](../../../references/papers/manifest.json)记录下载来源、页数与 SHA-256。
其中 AbaqusAgent 已保存 `2606.00138v1`；ALL-FEM 保存既有阅读所用的 arXiv v1，期刊 PDF 未归档；
ChemToolAgent 分别保存正式会议版和 arXiv v3。下载状态与下文的详读、源码核查和复现状态分别维护。

## 书目、来源与阅读定位

### 1. AbaqusAgent

Sarker et al. **A Multi-AI-agent Framework Enabling End-to-end Finite Element Analysis for Solid Mechanics Problems**.

[arXiv 记录](https://arxiv.org/abs/2606.00138) ·
[本文使用的 v1 全文](https://arxiv.org/html/2606.00138v1) ·
[作者代码仓库](https://github.com/LIRAM-LIN/AbaqusAgent) ·
[本仓库详细笔记](AbaqusAgent论文与源码详读.md)。

详读分别追踪案例检索、建模提示、运行反馈、论文评测和源码成功判定。源码基线为
`f5462b3eaf34d21a958f495b80e40df45b3f39db`，没有在本轮执行其 Agent 或 Abaqus 算例。

### 2. ChatCFD

**ChatCFD: A Large Language Model-Driven Agent for End-to-End Computational Fluid Dynamics Automation with Structured Knowledge and Reasoning**.

正式来源：[Wiley 论文页](https://advanced.onlinelibrary.wiley.com/doi/10.1002/aidi.202500174)，
DOI：`10.1002/aidi.202500174`。
配套实现：[ConMoo/ChatCFD](https://github.com/ConMoo/ChatCFD)。

已补充论文知识组织、修复、物理一致性评价及运行源码核查，记录用户提供网格、运行成功标志与物理评分的
区别。源码固定到 `2af6ca5d6f48657e5b1e09a588082fb8bb8e5790`；所读文件及具体证据见专题记录第 1 项。
尚未审计全部知识库或运行第三方实验。

### 3. 2D Frame 多 Agent

Geng et al. **A Lightweight Large Language Model-Based Multi-Agent System for 2D Frame Structural Analysis**.

来源：[arXiv:2510.05414](https://arxiv.org/abs/2510.05414)。本次未核实配套代码仓库。

已核查几何 JSON、专家规则、代码模板、重复实验及几何/代码合并消融，详见专题记录第 4 项。
仍需区分受控框架拓扑正确与通用材料、单元、网格和数值解正确，不能用少量消融结果代替总体工程能力。

### 4. ALL-FEM

**ALL-FEM: Agentic Large Language Models fine-tuned for finite element methods**.

正式 DOI：`10.1016/j.cma.2026.118985`。
[作者项目页及正式书目](https://fenics-llm.github.io/) ·
[出版社条目](https://www.sciencedirect.com/science/article/pii/S0045782526002586) ·
[arXiv:2603.21011](https://arxiv.org/abs/2603.21011)。

本次正式卷号、文章号由作者项目页的期刊书目核对，未取得出版社全文进行逐项比较。
期刊与预印本应分别保留元数据，不把某个版本的作者表、模型配置或成绩直接覆盖另一版本。

已阅读 v1 方法与实验，并核查题目预设建模条件、专家参考解叠图判分、人工终止循环和数字口径问题，
详见专题记录第 2 项。不能把摘要中的 code-level success 简化成“只检查代码运行”，也不能把明确给定
单元或简化假设的题目当作自主选择能力证据。完整训练/测试隔离与源码复现仍未完成。

### 5. CADCodeVerify

Alrashedy et al. **Generating CAD Code with Vision-Language Models for 3D Designs**.

正式来源：[ICLR 2025 proceedings](https://proceedings.iclr.cc/paper_files/paper/2025/hash/81a934cd364e18ea6fdeaf57a93c17d4-Abstract-Conference.html)。
[arXiv:2410.05340](https://arxiv.org/abs/2410.05340) ·
[作者代码仓库](https://github.com/Kamel773/CAD_Code_Generation)。

CADCodeVerify 是方法名，正式论文标题并非仅有这一名称。它利用 CAD 渲染图和视觉语言模型的问答检查
推动修正。对本项目最直接的启发是：代码执行和最终几何符合需求应分别验证。
但视觉模型判断不等于确定性的几何验收，更不能直接充当有限元物理 oracle；详读应检查验收指标、
错误类型和检视模型与生成模型之间的关系。

### 6. ChemCrow

Bran et al. **Augmenting large language models with chemistry tools**.

正式来源：[Nature Machine Intelligence](https://www.nature.com/articles/s42256-024-00832-8)，
DOI：`10.1038/s42256-024-00832-8`。
预印本：[ChemCrow: Augmenting large-language models with chemistry tools](https://arxiv.org/abs/2304.05376)。

该工作把专家设计的化学工具接入语言 Agent，并同时使用模型评价与专家评价。
预印本还指出，模型评价可能无法区分明显错误的回答与工具辅助结果。这里值得迁移的是工具职责划分和
独立评价意识；具体化学工具不属于本仓库范围。宜与下一篇连读，避免从成功案例推导“加工具必然提高表现”。

### 7. Tooling or Not Tooling? / ChemToolAgent

Yu et al. 的正式论文是 **Tooling or Not Tooling? The Impact of Tools on Language Agents for Chemistry Problem Solving**，
发表于 **Findings of the Association for Computational Linguistics: NAACL 2025**。

[ACL Anthology 正式记录](https://aclanthology.org/2025.findings-naacl.424/)，
DOI：`10.18653/v1/2025.findings-naacl.424`。
[arXiv:2411.07228](https://arxiv.org/abs/2411.07228) ·
[作者代码仓库](https://github.com/OSU-NLP-Group/ChemToolAgent)。

**不能再只标为“arXiv 论文”。** 正式会议版本保留旧标题；2025-05-26 的 arXiv v3 标题为
**ChemToolAgent: The Impact of Tools on Language Agents for Chemistry Problem Solving**，版本说明还提及新增实验。
引用正式结果时保留正式标题，使用新版实验时注明 v3；两者作为同一工作下的不同版本管理。

正式论文发现工具对专门化学任务和一般化学问答的价值并不一致。这对本项目的检索评测很有用：
应按知识缺口、工具选择、证据使用和最终任务验收分别看结果；工具可调用或返回了正确材料，不足以证明
最终任务获益。也不能把这种条件性结论简化成“领域工具没有用”。

### 8. Generic Harness 与 CAE 专用组件

Shi and Zhang. **What Do CAE Simulation Agents Really Need Beyond a Generic Harness?**

[arXiv:2609.03718v1](https://arxiv.org/abs/2609.03718) ·
[v1 全文](https://arxiv.org/html/2609.03718v1)。本次未核实配套代码仓库。

论文比较通用 Coding Harness、领域教程信息和额外 Agent 编排，是审视本项目“单 Agent 加领域知识”路线的
相关材料。阅读结果时必须连同其 limitations：每配置单次运行；若干专用系统成绩来自原论文，未用匹配的
新骨干模型重跑；各基准的验收尺度也不同，部分衡量运行完成而非数值正确。

因此，这项工作适合用于提出更公平的基线和信息对照，不能作为“多 Agent 已被证明不必要”或
“通用 Harness 已经解决物理建模”的定论。教程消融与跨论文成绩比较也应分开解读。

### 9. MCP-SIM

Park, Moon and Ryu. **A self-correcting multi-agent LLM framework for language-based physics simulation and explanation**.

正式来源：[npj Artificial Intelligence](https://www.nature.com/articles/s44387-025-00057-z)，
DOI：`10.1038/s44387-025-00057-z`。
[KAIST-M4/MCP-SIM](https://github.com/KAIST-M4/MCP-SIM) ·
[论文关联 Zenodo 记录](https://doi.org/10.5281/zenodo.15645333)。

这里 MCP-SIM 展开为 **Memory-Coordinated Physics-Aware Simulation**，不是 Model Context Protocol 的简称。
论文基于 FEniCS，通过共享记忆协调输入处理、代码生成、执行、诊断、改写与力学解释。

已阅读正文、补充材料 Note 1 与 Figures 1–2，并检查固定提交
`e30e08c4ffee52a64a1ecc63d7b57d91b13130ef` 的澄清器和执行器，详见专题记录第 3 项。
需要区分系统自动推断参数与向用户确认事实，以及公开执行器的错误检查与论文另行报告的物理评测。
本项目不能直接采用自动补造必需物理输入的行为；完整论文/源码对应关系尚未核实。

### 10. FEM-Bench

Mohammadzadeh, Hamdi, Shor and Lejeune. **FEM-Bench: A Structured Scientific Reasoning Benchmark for Evaluating Code-Generating LLMs**.

[arXiv 记录](https://arxiv.org/abs/2512.20732) ·
[本轮使用的 v2 全文](https://arxiv.org/html/2512.20732v2) ·
[作者代码仓库](https://github.com/elejeune11/FEM-bench)。

已核查任务辅助函数分层、参考输出容差比较、已知错误实现对生成测试的检验、重复实验设计与 Appendix D。
它适合为本项目设计知识/组合能力对照和验收器辨别力测试；不是直接衡量完整 Abaqus 工作流的基准。
具体方法与适用边界见专题记录第 6 项；本轮未运行该基准或完成源码审计。

## 后续详读使用同一组问题

每篇详细记录应保留六类内容：问题与能力边界、任务与知识来源、实际工作流、反馈与停止条件、
评测合同和结果、可迁移经验及其条件。核心问题是“哪些证据支持哪些结论”，而非罗列组件数量。

| 对照维度 | 记录要求 |
|---|---|
| 版本与材料 | 固定论文版本、发表状态、源码提交；分别注明全文阅读、源码核查和实际复现 |
| 建模知识与语法知识 | 哪些决策来自用户、模型、案例、规则或工具；资料是否带适用条件 |
| 输入与自主性 | 用户给到什么精度；允许哪些假设；缺必需输入时如何处理 |
| 检索与证据 | 检索对象、触发者、拒答或补查条件；案例与评测题是否同源 |
| 成功与成本 | 执行完成、需求符合、数值正确分别由谁验收；分母、失败成本、重试预算与重复次数 |
| 迁移与采用 | 哪个已观察问题值得借鉴；需要什么对照才可判定收益；不把候选建议写成已实现 |

与本项目当前问题的关联上，ChatCFD 和 2D Frame 支持分析显式建模知识与中间表示；
Generic Harness 与 ChemToolAgent 可用于审视基线和工具收益；CADCodeVerify 与 MCP-SIM 关注结果反馈；
ALL-FEM 提供领域微调路线，FEM-Bench 补充数值与测试验收方法。各项已完成的阅读深度以上表为准，
不因列入研究材料而视为新增架构或已实现能力。
