# 固定候选池重排对照：保留 MiniLM，不采用本次两个替代方案

日期：2026-09-11。本轮按用户确认的方向复核标签，并在相同候选池上比较当前 MiniLM、原候选顺序和
BGE v2-m3。**两个替代方案都没有增加新版必要证据覆盖，且丢失原有热传导条件，完整覆盖题目从 5/7 降到
4/7；BGE 的 CPU 打分成本还明显增加。因此均未采用，不改变产品默认或现有候选基线。**

## 标签先复核，再冻结实验

16 个原问题及其 context/product/release 全部不变。直接核对原始目标段落及来源绑定后，只做两个显式修订：

1. history 题原标签要求一个“默认浮点精度”的背景段落；原问题实际询问 history 的存储精度及 full 能否
   改变它。新标签改为官方 `output_precision` 定义中对 history 单精度和 field/full 范围的直接说明。
   这不是宣称两段全文等价：新定义并未说明旧标签中的默认 field 精度。
2. 热膨胀题新增“初始温度与系数参考温度不同”的必要条件，采用此前仅作为源段诊断的完整说明段，并保留
   既有公式关联交付。不能把零初始热应变外推为零总机械应力。

其余九项旧条件经源文复核后保持。新版为 **7 个有标注问题、11 项必要条件**；旧版 10 项仍并列计分，旧
数据集和旧报告完全不改写。新标签由同一助手复核，不是独立人工双标，也不是新 held-out。

## 三组实际结果

| 排序条件 | 旧标签最终覆盖 | 新标签最终覆盖 | 新标签完整覆盖题目 | 新标签必要父单元 MRR@64 | 模型打分耗时 |
|---|---:|---:|---:|---:|---:|
| 当前 MiniLM | 6/10 | **7/11，63.6%** | **5/7，71.4%** | 0.7584 | 18.07 秒 |
| 原候选顺序，无学习式重排 | 7/10 | 7/11，63.6% | 4/7，57.1% | 0.6786 | 无模型打分 |
| BGE v2-m3 | 7/10 | 7/11，63.6% | 4/7，57.1% | **0.8333** | 403.13 秒 |

所有条件的新标签候选覆盖均为 10/11；固定池没有变化。两个独立源段诊断均为 1/2 完整交付：history
规则送达，热膨胀初始/参考温度说明未送达。MRR 只奖励第一条已标注必要证据靠前，不能替代完整条件覆盖；
BGE 的 MRR 更高，却少完成一个有标注问题，正是这个区别的实际例子。

标签修订使**同一个 MiniLM、同一份证据**的成绩从旧口径 6/10、4/7 变为新口径 7/11、5/7；这部分变化
来自评价口径，不是模型改善。反过来，只看旧口径的 7/10 也会掩盖两个替代方案丢失热传导条件的事实。
所有“完整”均指全部已标注条件，不是生成答案正确率或完整物理判断。

## 增益和损失发生在哪里

- **Riks**：原候选顺序和 BGE 都比 MiniLM 多送达了 LPF/载荷比例关系段，但仍没有送达边界条件的
  amplitude 限制段，所以该题仍未覆盖完整标注。不能从载荷示例列表推出“只能使用力载荷”。
- **稳态/瞬态热传导**：两个替代方案保留瞬态材料要求，却丢掉了稳态内部能量项省略的明确说明。
  这是它们相对当前 MiniLM 的共同回归。
- **热膨胀**：初始/参考温度说明在 MiniLM、原池顺序、BGE 的子片段位置分别为 **63、14、32**，均未送达。
  BGE 改善了这一个位置，但仍未转化为必要证据交付。
- 参考系数条件另需的 `4f3812…da082` 段落没有进入原 Dense64/BM2564；三组固定池都缺少它，换重排器不能
  找回候选池外的内容。其配套 `9ba719…5cd9` 段落虽在池内，单独取得也不满足原 AND 条件。

实验结束后还只读检查了 BGE 的实际 Top4：热传导结果主要说明瞬态材料、比热、对流和非线性；没有直接
替代被标注的稳态内部能量省略说明。Riks 的 Loads/amplitude 文字也不能自动替代 BC/amplitude 的约束。
这是事后解释，不回填标签或分数，也不宣称已穷尽所有等价证据。

## 如何控制变量

- 复用上一批保存的候选池：10 个需要重排的问题、共 **640 个问题—片段对**。问题和 `passage_text` 字符串
  完全相同；不重新执行 Dense/BM25、不生成新文档向量，不改变父单元、范围和索引。
- 当前 MiniLM 重新评分，逐项核对原排名及 logit（绝对误差不超过预设 1e-5），完整交付正文与原结果相同。
- 原候选顺序包含既有页面补充顺序，不是“最优 RRF-only 排名”；序号只用于维持顺序，不是相关性置信度。
- 三组共用原交付代码和公式关联后处理：最多 4 个单元、每段 1200 proxy tokens、序列化证据合计 4000。
  所有实际交付都重新检查来源、范围、正文和预算。
- 两个学习式模型均使用 CPU、4 线程、batch=8。MiniLM 使用原 ONNX 路径，BGE 使用隔离环境中的 PyTorch
  FP32/eager；不同运行时和 tokenizer 属于被比较的组件配置，不声称单独分离了模型架构效应。
- BGE 的 640 个原生 token 长度在推理前全部检查，最大 **434**，没有输入截断。
- 六个没有候选池的符号/版本/长度用例直接回放历史结果，显式标注未新执行；其中五项 guard 的值保持通过。
  它们不是本轮重新执行的符号工具或安全测试。

源码、标签、原问题/片段、模型、运行依赖及预检结果均在三组排名前绑定。每个学习式模型正式处理 640 对，
无学习式重排组没有模型推理。旧 scorer 中 `reranked_pairs` 字段在回放中表示提供的排名行数；实际模型工作量
以各组的 `model_inference_pairs` 为准，不能把无模型组也算成 640 次推理。

## BGE 来源与运行成本

使用[官方 BAAI/bge-reranker-v2-m3](https://huggingface.co/BAAI/bge-reranker-v2-m3)，固定 revision
`953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e`。只获取数据文件，权重约 2.27 GB，按官方 LFS SHA-256 验证；
小文件另外验证 Git blob 身份。保留原 README 和来源记录，不执行仓库 Python，不加载 pickle 权重。

独立运行环境为项目内 `var/experiments/bge-rerank-v1/.venv`，Python 3.12.11、torch 2.8.0+cpu、
transformers 4.57.1、safetensors 0.6.2。主项目 `.venv`、`uv.lock` 和 `pyproject.toml` 未改变。
首次安装曾遇到 Windows 启动器资源更新错误；再次检查安装后，依赖一致性、实际 import 和模型预检均通过，
没有关闭系统安全功能。

在正式任务评分前，8 对与任务无关的合成文本用于运行预检：约 4.31 秒，峰值工作集约 1.94 GiB。
正式 BGE 打分约 **403.13 秒**，启动约 6.61 秒，峰值工作集约 **2.67 GiB**；在预设 900 秒上限内完成。
当前 MiniLM 打分约 18.07 秒，本机观察相差约 **22.3 倍**。两条实现的 token 预计算与排序计时边界略有差别，
这些数字用于本次组件成本判断，不是受控硬件吞吐 benchmark 或线上 SLO；无重排组也不是端到端零耗时。

## 验证与决策

新增固定池回放模块和 **11 项测试**，覆盖输入/池顺序、源文本、适用范围、分数与长度、禁止新召回，以及
相同排序的交付复现；与现有基线测试合计 **36 passed**，全仓 **981 passed、27 skipped**。
新源码 Ruff/BasedPyright 通过；全部冻结输入、旧证据和新结果的 hash 在结束后核对。

预先定义的选择条件是：增加新版完整覆盖题数，且不丢失任何原先满足的新版必要条件。两个替代方案都使
完整题数减少 1，并丢失 `steady_internal_energy`，因此不满足条件。**保留当前 MiniLM，不连续尝试其他模型，
不改门槛，也不切换默认路径。**若继续优化，仍需另行处理多条件覆盖和那个候选池外的召回缺口；本轮没有
实施这些新策略。

生成式查询/答案调用 **0**，Agent/Abaqus 调用 **0**。本轮只有本地重排模型推理，不能把结果描述为真实
问答正确率、泛化收益或 Agent 任务收益。
