# Legal512 跨文档分组对照：保留候选，不全量切换

## 结论

这次验收不足以支持全量改用 LLM 切块。LLM 路在可处理题目上为 **10/10**，确定性路为 **8/10**，但两题差异全部来自此前已暴露的 Riks 页；新增且可处理的三页六题，两路均为 **6/6**。另外两页因现有结构/容量边界未进入任何一路索引，不能从分母中消失：包含这些失败后分别为 **10/14** 与 **8/14**。

工程判断是保留 LLM 作为显式实验候选，默认索引不变；先面对公式投影与表格合法切点这两个共同缺口。这里没有预先定义一个“提升两题即通过”的产品门槛，也不是新的 held-out 或 Agent 任务收益证据。

## 固定口径

- 结构类别先定页，未因预检查失败换页：旧 Riks 回归，加输出频率、`*BOUNDARY` 参数、梁截面公式、预选输出表格、两产品的输出代码示例。
- 在新分组、索引与排名前冻结 14 个问题及原文字符位置；Riks 沿用原四题和证据。LLM 只看到原文合法单元，不看到问题或 gold。其他题是人工阅读原文后的 development 标注，不是独立盲测。
- 两路使用同一已有 `sentence-structure-legal-cuts-v1`、原文投影、384-token 正文上限、512-token MiniLM 独立适配器和固定 cross-encoder；没有修改这些实现或权重。
- 确定性路把整页视为一个逻辑组，复用合法边界长度保护器做最大长度贪心分组。LLM 路只决定合法单元如何分组，再经过相同保护器。这是一个简单的确定性对照，不代表所有确定性算法的上限。
- 每路在同一组可处理页面上建独立 Dense/BM25 索引；Dense20 与 BM2520 取并集，再使用同一 cross-encoder。实际共有 36 / 72 个块。
- 返回预算固定为 **1,024 MiniLM WordPiece tokens**，包含 `Title`、`Section` 和分隔符。按排名扫描，装不下的整块跳过，继续检查后续块；不剪短块、不限定必须返回四块、不补到相同实际长度。这不是 Flash 的计费token口径。
- Source Recall/Precision/IoU 使用带 document ID 的规范化原文 token 位置；Precision 只表示与已标注必要证据的重合，不是完整的语义相关性精度。
- 不支持的 content 投影或一个合法原子超出384tokens，即整页在两路同时阻断。导航单元与正文区分；没有把不支持的公式默默丢掉后声称全页成功。

## 同预算数值

以下均仅对可处理的10题计算均值；另外4题是显式预检查失败，不伪造数值 Recall。

| 指标 | 确定性 | LLM |
|---|---:|---:|
| 完整必要证据召回 | 8/10 | 10/10 |
| 必要证据token Recall | 0.8000 | 1.0000 |
| 必要证据token Precision | 0.2467 | 0.2584 |
| token IoU | 0.2467 | 0.2584 |
| 实际返回tokens均值 | 915.7 | 990.1 |
| 未使用预算均值 | 108.3 | 33.9 |
| 编码输入最大tokens，含特殊token | 384 | 370 |
| 重排query/passage pair最大tokens | 437 | 427 |

相同上限下，LLM实际平均多返回74.4tokens，约8.1%；因此不能说它更省上下文。两个差异题是完整丢失或完整找到，其余题两路均完整覆盖，所以此处Precision与IoU数值相同。

## 差异与关系检查

两道确定性失败并非原文缺失，也不是 gold 没进候选池：

- `riks-boundary-amplitude`：含gold的369-token块排在第3，前两块来自 `*BOUNDARY` 页；剩余预算装不下该块。LLM对应119-token块排第1并被返回。
- `riks-termination`：含gold的377-token块排第4，扫描时剩余预算不足。LLM对应123-token块排第1并被返回。

这说明该次分组同时改变了重排聚焦程度与整块预算装填，不应把差异单独解释成“LLM更懂语义”。它也未在新增页上复现完整召回增益。

结构完整性检查：两路都原样、无重叠、无丢失地覆盖各自规范化可处理全文，所有已声明的 no-cut span 均为零违规；所有 `[Code]` 块保持完整，实际编码和重排均无截断。但零规则违规不等于完整语义关联：

- LLM把Standard输出示例的解释和整段代码放在同块；确定性路把该代码与下一节Explicit解释放在同块，尽管并未切断代码。
- LLM的Explicit逻辑组仍被长度保护器拆为解释块和代码块；本次两块都被取回，不能据此声称单块就完整表达整个示例。
- 两路在Riks initial-increment的较大源段中都有相同切点，说明冻结的保护规则仍不覆盖所有隐式跨句关系。
- 机器报告的“gold整段在一个块内”按原始字符范围计数为11/14和12/14；LLM的FIXED标注跨块仅因末尾空白，不是语义丢失。因此不把这个原始字符指标当成关系理解分数，也未据观察到的结果修改gold或重跑排名。

## 成本、验证与取舍

4次Flash请求全部首次接受，无重试；合计23,965 input tokens、644 output tokens，模型调用耗时10.27秒。每页最多2次的上限未用尽；两页预检查失败没有模型调用。费用字段不可用，未估算金额。LLM形成69个逻辑组，长度保护额外增加3个边界，最终72块；确定性为36块。

两个索引在查询前绑定完整语料、BM25数据库、存储向量及HNSW文件摘要；独立评测进程重新打开并校验，查询后再次检查向量与实现未漂移。没有修改Chroma默认encoder、默认 `var/rag`、产品工具或Agent；没有运行Abaqus。

新增 `evaluation/chunk_acceptance.py` 只负责离线整块预算和源位置指标。相关10个测试文件合计 **111 passed**；新增文件及实验脚本Ruff检查和格式检查通过。测试验证工程合同，不代表真实Agent收益。

下一步建议（尚未实施）：分别为现有表格行及不支持的MathML确定可复核的表示/合法边界，再用新版本独立复验；保留本次失败和冻结结果。不再根据这些已暴露题目调Riks分组，也不以本次10/10为理由全量重建。
