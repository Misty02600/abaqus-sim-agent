# 同一 MiniLM 权重的长输入验证与 Riks 许可切点试验

## 结论

同一份已绑定 ONNX 权重可以实际运行 512-token 输入，无需先下载另一款 embedding 模型。独立实验适配器关闭截断，超限输入在执行前拒绝；没有修改 Chroma 的默认实现、缓存 tokenizer 或默认索引。

这只证明运行路径与本页验证成立，不代表官方默认支持 512-token 语义质量，也不代表任意长文本的检索效果可靠。模型卡将其定位为短句／短段落编码器，默认截断 256 word pieces，训练时序列长度为 128。

## 运行证据

- 实际 512-token 输入成功输出 384 维有限向量，范数约 1。
- 相同短输入与 Chroma 默认编码器的最大绝对差为 **0**。
- 两段文本的前 256 token 相同，只有后段不同：默认 tokenizer 产生相同的截断输入；长输入适配器所得向量的 L2 差约 **0.9034**。因此不是仅修改了上限数字，后段确实参与了计算。
- 513-token 输入被拒绝；测试证明整批有超限输入时，尚未执行模型。
- 独立索引按同一长输入适配器重新打开并查询；向量摘要、HNSW 摘要和 Dense/BM25 语料一致性检查通过。

## 同页试验

继续使用此前完全相同的 Riks 规范化正文、94 个句子／结构定位单元，以及原来的 4 个问题。

- 编码器上限：512 token（含特殊 token）。
- 最终正文块目标上限：384 token，为重排的问题与标题留空间，并对所有问题—片段组合实际计数检查。
- Flash 非思考模式一次响应，约 **2.59 秒**，输入 5,801、输出 107 token，未报告思考 token。
- 模型提出 21 组；长度保护只在许可切点增加一个边界，最终 **22 块**。
- 最长正文块为 336 token，编码输入为 **338 token**。
- 所有问题—片段组合中，重排输入最长 **380 token**，没有静默截断。
- 保护区间内的切点数量为 **0**。

此前容量冲突的源区间 `[4576, 5392)` 完整保留在最终块 7 `[4576, 5521)` 中：直接引导语、公式、where 解释，以及相关用法标签／代码一起保存。原问题还取回了相邻的初始步长介绍；这不意味着所有数学背景都只需要一个块。

## 检索结果

| 问题 | 完整标注证据 | 返回的源 token |
|---|---:|---:|
| 比例载荷与公式 | 是 | 612 |
| 边界条件幅值 | 是 | 688 |
| 初始增量关系 | 是 | 853 |
| 终止条件 | 是 | 697 |

平均返回 **712.5 token**，比此前 Flash＋普通长度保护的 574.75 更多。主要改善是消除了已明确保护的拆分问题、使超出旧容量的内容真正参加编码和检索；不能将其表述为更省 token 或一般检索质量提升。

边界约束、允许块长和编码路径同时改变，因此不是单因素消融。仍只有一个源知情开发页面，不能外推 Agent 任务成功率或任意工程文档。
